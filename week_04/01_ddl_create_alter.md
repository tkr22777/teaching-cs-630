# DDL: CREATE and ALTER Statements

## Overview

**DDL (Data Definition Language)** commands define the structure - the tables, columns, and rules. This guide covers CREATE and ALTER commands for creating and modifying tables.

## CREATE TABLE

When you start a new project or need to store new types of information, you'll use CREATE TABLE to define the structure. This tells the database what columns you need, what type of data goes in each column, and what rules the data must follow.

### Basic Syntax

```sql
CREATE TABLE table_name (
    column1 datatype constraints,
    column2 datatype constraints,
    ...
    table_constraints
);
```

### Example 1: Simple Table with Primary Key

**SQL Statement:**

```sql
CREATE TABLE students (
    student_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    first_name VARCHAR2(50) NOT NULL,
    last_name VARCHAR2(50) NOT NULL,
    email VARCHAR2(100) UNIQUE,
    enrollment_date DATE DEFAULT SYSDATE  -- SYSDATE is the current date/time
);
```

**Table Structure Created:**

| Column          | Type          | Constraints          |
| --------------- | ------------- | -------------------- |
| student_id      | INTEGER       | GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY |
| first_name      | VARCHAR2(50)  | NOT NULL             |
| last_name       | VARCHAR2(50)  | NOT NULL             |
| email           | VARCHAR2(100) | UNIQUE               |
| enrollment_date | DATE          | DEFAULT SYSDATE      |

The `GENERATED BY DEFAULT AS IDENTITY` clause automatically generates unique ID values for each new row, eliminating the need to manually specify IDs when inserting data.

Now let's look at how tables connect to each other through foreign keys.

### Example 2: Table with Foreign Key

**SQL Statement:**

```sql
CREATE TABLE courses (
    course_id VARCHAR2(10) PRIMARY KEY,
    course_name VARCHAR2(100) NOT NULL,
    credits INTEGER CHECK (credits > 0 AND credits <= 6),
    department VARCHAR2(50) NOT NULL,
    instructor_id INTEGER,
    FOREIGN KEY (instructor_id) REFERENCES instructors(instructor_id)
);
```

**Table Structure Created:**

| Column        | Type          | Constraints                               |
| ------------- | ------------- | ----------------------------------------- |
| course_id     | VARCHAR2(10)  | PRIMARY KEY                               |
| course_name   | VARCHAR2(100) | NOT NULL                                  |
| credits       | INTEGER       | CHECK (credits > 0 AND credits <= 6)      |
| department    | VARCHAR2(50)  | NOT NULL                                  |
| instructor_id | INTEGER       | FOREIGN KEY → instructors(instructor_id) |

The **foreign key** ensures that every course has a valid instructor - you can't assign a course to an instructor that doesn't exist in the instructors table. Foreign keys create links between tables.

When you need to represent many-to-many relationships (like students enrolling in multiple courses, and courses having multiple students), you'll use a **junction table** (also called a linking table or join table).

### Example 3: Junction Table with Composite Primary Key

**SQL Statement:**

```sql
CREATE TABLE enrollments (
    student_id INTEGER,
    course_id VARCHAR2(10),
    semester VARCHAR2(20),
    grade VARCHAR2(2),
    enrollment_date DATE DEFAULT SYSDATE,
    PRIMARY KEY (student_id, course_id, semester),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
```

**Table Structure Created:**

| Column          | Type         | Constraints                      |
| --------------- | ------------ | -------------------------------- |
| student_id      | INTEGER      | Part of PRIMARY KEY, FOREIGN KEY |
| course_id       | VARCHAR2(10) | Part of PRIMARY KEY, FOREIGN KEY |
| semester        | VARCHAR2(20) | Part of PRIMARY KEY              |
| grade           | VARCHAR2(2)  |                                  |
| enrollment_date | DATE         | DEFAULT SYSDATE                  |

A **composite primary key** uses multiple columns together to uniquely identify a row. In this case, (student_id, course_id, semester) means a student can take the same course in different semesters, but not twice in the same semester.

## Common Data Types

These are the data types you'll use most often:

| Type          | Use For                    | Example               |
| ------------- | -------------------------- | --------------------- |
| INTEGER       | Whole numbers              | 42                    |
| NUMBER(10,2)  | Money, decimals            | 99.99                 |
| VARCHAR2(100) | Text (names, emails, etc.) | 'John Doe'            |
| DATE          | Dates and times            | DATE '2024-01-15'     |

### Constraints

Constraints enforce rules on your data:

| Constraint  | What It Does                | Example              |
| ----------- | --------------------------- | -------------------- |
| PRIMARY KEY | Uniquely identifies row     | PRIMARY KEY          |
| FOREIGN KEY | Links to another table      | REFERENCES table(id) |
| NOT NULL    | Must have a value           | NOT NULL             |
| UNIQUE      | No duplicates allowed       | UNIQUE               |
| CHECK       | Custom rule                 | CHECK (age >= 18)    |

## ALTER TABLE

After creating a table, you'll often need to modify it - add new columns as requirements change, modify existing columns, or adjust constraints. That's what ALTER TABLE does. It changes the structure without losing your existing data.

Let's work with a simple products table to see different ALTER operations.

### Sample Data for ALTER Examples

First, let's create and populate a sample table:

```sql
CREATE TABLE products (
    product_id INTEGER PRIMARY KEY,
    product_name VARCHAR2(100) NOT NULL,
    price NUMBER(10, 2)
);

INSERT INTO products (product_id, product_name, price) VALUES
(1, 'Laptop', 999.99);
INSERT INTO products (product_id, product_name, price) VALUES
(2, 'Mouse', 25.50);
INSERT INTO products (product_id, product_name, price) VALUES
(3, 'Keyboard', 75.00);
```

**Current Products Table:**

| product_id | product_name | price  |
| ---------- | ------------ | ------ |
| 1          | Laptop       | 999.99 |
| 2          | Mouse        | 25.50  |
| 3          | Keyboard     | 75.00  |

### ALTER: Adding a Column

**SQL Statement:**

```sql
ALTER TABLE products 
ADD stock_quantity INTEGER DEFAULT 0;
```

**Result - Updated Table Structure:**

| product_id | product_name | price  | stock_quantity |
| ---------- | ------------ | ------ | -------------- |
| 1          | Laptop       | 999.99 | 0              |
| 2          | Mouse        | 25.50  | 0              |
| 3          | Keyboard     | 75.00  | 0              |

Notice how the new column was added to all existing rows with the default value of 0. This is safer than adding a column without a default when you have existing data.

If you realize you don't need a column anymore, you can remove it entirely.

### ALTER: Dropping a Column

**SQL Statement:**

```sql
ALTER TABLE products 
DROP COLUMN stock_quantity;
```

**Result - Updated Table:**

| product_id | product_name | price  |
| ---------- | ------------ | ------ |
| 1          | Laptop       | 999.99 |
| 2          | Mouse        | 25.50  |
| 3          | Keyboard     | 75.00  |

You can add constraints to existing tables to enforce new data quality rules.

### ALTER: Adding and Dropping Constraints

**Add Constraints:**
```sql
-- Add UNIQUE constraint
ALTER TABLE products 
ADD CONSTRAINT unique_product_name UNIQUE (product_name);

-- Add CHECK constraint
ALTER TABLE products 
ADD CONSTRAINT check_positive_price CHECK (price > 0);
```

**Drop Constraint:**
```sql
ALTER TABLE products 
DROP CONSTRAINT check_positive_price;
```

## Summary

**CREATE TABLE** defines new tables with columns, data types, and constraints. **ALTER TABLE** modifies existing tables.
